03 Review

How to decide in ten minutes.

You do not need to read the code. Open each demo, use it like a customer, then like a dispatcher.

Review checklist

Each demo has the same five tabs, so you are comparing voice and density — not features.

  1. Landing first. Does it explain the service in one screen, and would you trust it with your car?
  2. Customer tab. Find the ETA, the driver, and the price without hunting. This is the anxious-user test.
  3. Driver tab. Can a technician tell what to do next in under two seconds, outdoors, on a phone?
  4. Dispatch tab. Can a controller scan ten rows and spot the one that is late?
  5. Notes tab. Read the trade-off each direction admits to. Pick the risk you can live with.

What happens after you pick

One direction becomes the design system; the others stay as reference.

  1. Lock tokens. Colour, type, radius, spacing, and motion go into the Tailwind theme and a short design notes file.
  2. Scaffold. Next.js 16 App Router, strict TypeScript, shadcn primitives, module folders from the architecture doc.
  3. Build the slice. Auth → vehicle → request → dispatch → tracking, with the security tests from day one.

Mixing is allowed. If you want A's customer flow with B's dispatch console, say so — that is a normal outcome, and the block structure already supports it.
